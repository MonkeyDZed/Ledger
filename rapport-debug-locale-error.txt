# Rapport d'Analyse pour Debugging Externe - Erreur "Incorrect locale information provided"

Ce document synthétise toutes les informations disponibles concernant le projet et le bug persistant, en réponse au questionnaire de l'expert en debugging.

---

### **1. Contexte projet**

*   **Stack exacte utilisée :**
    *   **Framework :** Next.js v15.3.3 (avec App Router et Turbopack). Le projet utilise aussi React v18.3.1 et TypeScript v5.
    *   **Version Node.js :** L'environnement est configuré pour Node.js v20.x.
    *   **Base de Données (BDD) :** SQLite, via les packages `sqlite` (v5.1.1) et `sqlite3` (v5.1.7). Le fichier de base de données est `database.db` à la racine.
    *   **Hébergement :** L'application est exclusivement déployée et exécutée dans l'environnement **Firebase Studio**, qui utilise Firebase App Hosting.

*   **Localisation de l'application :**
    *   L'application est déployée sur **Firebase App Hosting** via Firebase Studio. Elle n'est pas exécutée en local sur une machine de développement standard.

---

### **2. Problème précis**

*   **Description exacte du bug :** L'application affiche une page d'erreur Next.js avec le message principal **`Incorrect locale information provided`**. Ce symptôme indique typiquement qu'un module `'server-only'` (ou une de ses dépendances) est importé dans un composant ou un module qui fait partie du graphe de dépendances client (`'use client'`).

*   **Moment d'apparition :** L'erreur apparaît **à l'exécution**, lors d'une tentative de rendu d'une page qui contient un composant client important (comme le tableau de bord ou la liste des fournisseurs). Le serveur de développement démarre correctement, mais le rendu de la page échoue.

*   **Message d'erreur complet :**
    ```
    Error: Incorrect locale information provided
    ```
    Cette erreur est généralement accompagnée d'une pile d'appels qui pointe vers des modules Next.js internes, rendant le débogage direct difficile, mais la cause est systématiquement une "contamination" du graphe de dépendances client.

---

### **3. Logs & Erreurs**

*   **Log complet du terminal Firebase Studio :** Les logs du serveur montrent un démarrage réussi, suivi d'une compilation des pages demandées. L'erreur n'apparaît pas dans les logs de démarrage, mais se manifeste comme une erreur de rendu lorsque la page est accédée.
    ```
    ✓ Ready in X.Xs
    ○ Compiling /[lang]/dashboard ...
    ```
    (L'erreur de rendu apparaît ensuite dans le navigateur, pas nécessairement dans la console de démarrage du serveur).

*   **Reproduction en local :** L'environnement étant exclusivement Firebase Studio, il n'y a pas de "rebuild en local" standard. Le problème est persistant et reproductible à chaque rendu de page dans l'environnement fourni.

### **5. Branches & Git**

*   **Branche Git :** Le développement se fait sur une seule branche principale, il n'y a pas de branches multiples.
*   **Existence du problème :** Le problème existe sur l'unique branche du projet.

---

### **6. Tests et Contournements**

*   **`npm run dev` :** C'est la commande exacte que le serveur lance pour démarrer, et le problème persiste.
*   **`firebase emulators:start` :** Non pertinent pour ce projet qui utilise App Hosting et non les émulateurs.
*   **Suppression de `node_modules` et `npm install` :** L'environnement Firebase Studio gère les dépendances de manière transparente. Les multiples redémarrages et reconstructions équivalent à cet état propre. Le problème n'est pas lié à un `node_modules` corrompu.
*   **Autre version de Node.js :** Non testé, car l'environnement est fixe sur Node.js 20.x.

---

### **7. Objectif final**

*   **Action souhaitée :** L'objectif est d'avoir une application qui s'exécute correctement dans l'environnement de prévisualisation de Firebase Studio, sans l'erreur `Incorrect locale information provided`.
*   **Deadline :** Il n'y a pas de deadline critique, mais la résolution de ce bug est la priorité absolue car il bloque tout développement et test. Il s'agit d'un debug normal mais bloquant.
