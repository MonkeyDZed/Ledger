# Rapport d'Analyse pour Debugging Externe - Erreurs "Incorrect locale information" et "Sauvegarde impossible"

Ce document synthétise toutes les informations disponibles concernant le projet et les bugs persistants, en réponse au questionnaire de l'expert en debugging.

---

### **1. Contexte projet**

*   **Stack exacte utilisée :**
    *   **Framework :** Next.js v15.3.3 (avec App Router et Turbopack). Le projet utilise aussi React v18.3.1 et TypeScript v5.
    *   **Version Node.js :** L'environnement est configuré pour Node.js v20.x.
    *   **Base de Données (BDD) :** SQLite, via les packages `sqlite` (v5.1.1) et `sqlite3` (v5.1.7). Le fichier de base de données est `database.db` à la racine.
    *   **Hébergement :** L'application est exclusivement déployée et exécutée dans l'environnement **Firebase Studio**, qui utilise Firebase App Hosting.

*   **Localisation de l'application :**
    *   L'application est déployée sur **Firebase App Hosting** via Firebase Studio. Elle n'est pas exécutée en local sur une machine de développement standard.

---

### **2. Problèmes Précis**

Le projet souffre de deux problèmes majeurs et potentiellement liés :

**Problème A : Erreur de Rendu "Incorrect locale information provided"**
*   **Description exacte :** L'application affiche une page d'erreur Next.js avec le message principal **`Incorrect locale information provided`**. Ce symptôme indique typiquement qu'un module `'server-only'` (ou une de ses dépendances, comme `getDictionary`) est importé dans un composant ou un module qui fait partie du graphe de dépendances client (`'use client'`).
*   **Moment d'apparition :** L'erreur apparaît **à l'exécution**, lors d'une tentative de rendu d'une page contenant des composants clients complexes (comme le tableau de bord).

**Problème B : Bouton de Sauvegarde Inactif (Bug Fonctionnel)**
*   **Description exacte :** Lors de la tentative de **modification** d'une pièce existante (Facture ou BL), le formulaire s'affiche correctement avec les données pré-remplies. Cependant, le bouton "Sauvegarder" reste **désactivé (disabled)**, empêchant toute soumission. Ce bug ne se produit pas lors de la création d'une nouvelle pièce, seulement en mode édition.
*   **Cause probable :** Ce comportement est typique d'un problème de validation avec `react-hook-form` et `zod`. Le formulaire est considéré comme invalide (`formState.isValid` est `false`) dès son chargement, probablement parce que les valeurs par défaut chargées pour la modification ne satisfont pas les règles du schéma de validation `clientPieceFormSchema` défini dans `PieceForm.tsx`.

---

### **3. Logs & Erreurs**

*   **Logs pour Problème A :** Les logs du terminal Firebase Studio montrent un démarrage réussi, mais l'erreur de rendu apparaît ensuite dans le navigateur, pas nécessairement dans la console de démarrage.
*   **Logs pour Problème B :** Il n'y a pas de message d'erreur dans la console pour ce bug, car il s'agit d'un état de l'interface utilisateur (bouton désactivé) et non d'une erreur d'exécution.

*   **Reproduction en local :** L'environnement étant exclusivement Firebase Studio, il n'y a pas de "rebuild en local" standard. Les problèmes sont persistants et reproductibles dans l'environnement fourni.

---

### **4. Code & Config**

*   **`package.json` :** Les dépendances clés sont `next@15.3.3`, `react-hook-form`, `zod`, `sqlite`, `sqlite3`. (Le contenu complet est dans le fichier `package.json` à la racine).
*   **`firebase.json`, `.firebaserc` :** Inexistants, car le projet est géré par Firebase Studio. La configuration est dans `apphosting.yaml`.
*   **Fichiers `.env` :** Aucun fichier `.env` n'est configuré.

---

### **5. Branches & Git**

*   **Branche Git :** Le développement se fait sur une seule branche principale.
*   **Existence du problème :** Les problèmes existent sur l'unique branche du projet.

---

### **6. Tests et Contournements**

*   **Tests effectués :** De multiples tentatives de refactorisation ont été faites pour résoudre le Problème A, notamment en essayant d'isoler les dépendances serveur, sans succès durable.
*   **`npm run dev` :** C'est la commande de démarrage standard, les problèmes persistent.
*   **Suppression de `node_modules` :** L'environnement gère cela de manière transparente ; le problème n'est pas lié à un cache de dépendances corrompu.

---

### **7. Objectif final**

*   **Action souhaitée :** Rendre l'application fonctionnelle en prévisualisation. La priorité absolue est de **résoudre le Problème B (sauvegarde impossible)**, car il bloque un workflow utilisateur essentiel. La résolution du Problème A est également nécessaire pour la stabilité globale.
*   **Deadline :** Il n'y a pas de deadline critique, mais la résolution de ces bugs est la priorité car ils bloquent tout développement et test.
